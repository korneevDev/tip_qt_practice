# Занятие 13. PostgreSQL, тестирование и подготовка веб-приложения к запуску

## Цель

Освоить создание связанных таблиц PostgreSQL и безопасное обращение к ним из Node.js. Реализовать постоянное хранение данных, автоматизированные проверки и воспроизводимую конфигурацию приложения.

## Теория

### 1. Зачем нужна база данных

На занятии 12 сведения хранились в массиве `tasks`. Он существует только в оперативной памяти Node.js и исчезает после остановки сервера. База данных хранит данные независимо от процесса приложения и позволяет управлять ими с помощью запросов. Здесь используется PostgreSQL — система управления реляционными базами данных.

**База данных** содержит таблицы; **таблица** содержит строки (записи) и столбцы (поля). Одна строка таблицы `tasks` — одна задача, а столбец `title` — её название. Две связанные таблицы предпочтительнее повторения названия категории в каждой задаче.

```text
categories                        tasks
+----+----------+               +----+--------------+-------------+-----------+
| id | name     |               | id | title        | category_id | completed |
+----+----------+               +----+--------------+-------------+-----------+
|  1 | Учёба    |<--------------|  5 | Сдать отчёт  |           1 | false     |
|  2 | Проект   |<--------------|  6 | Создать сайт |           2 | true      |
+----+----------+               +----+--------------+-------------+-----------+
```

`categories.id` — первичный ключ; `tasks.category_id` — внешний ключ. Внешний ключ предотвращает создание задачи со ссылкой на несуществующую категорию. `NOT NULL` запрещает отсутствие значения, `UNIQUE` запрещает повтор, `CHECK` задаёт условие, которое база проверяет независимо от программы.

### 2. Первые команды в psql

`psql` — консольный клиент PostgreSQL. При локальной установке на Windows он может не находиться в `PATH`; тогда откройте SQL Shell (psql) из установленного PostgreSQL или укажите путь к `psql.exe`. Для дальнейших команд подключение должно использовать пользователя с правом создавать учебную базу.

```sql
CREATE DATABASE tip_tasks;
```

Команда создаёт базу. Выполните её один раз, подключившись к служебной базе `postgres`. Затем переключитесь в новую базу (`\c tip_tasks` внутри `psql`) и проверьте соединение командой `SELECT current_database();`. Важно: `\c` — команда самого клиента psql, а не SQL. SQL-запросы заканчиваются точкой с запятой.

Для повторного выполнения схемы можно использовать команду из терминала (пароль вводится интерактивно):

```bash
psql -h 127.0.0.1 -U postgres -d tip_tasks -f sql/001_schema.sql
```

Учебный сервер может предоставлять отдельную учётную запись и базу. В таком случае используйте выданные преподавателем параметры. **Не создавайте новый сервер PostgreSQL, если учебная база уже предоставлена.**

### 3. SQL: создание и заполнение таблиц

`CREATE TABLE` описывает структуру, а `INSERT` добавляет записи. Пример минимальной таблицы:

```sql
CREATE TABLE categories (
    id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name varchar(40) NOT NULL UNIQUE
);
INSERT INTO categories (name) VALUES ('Учёба'), ('Проект'), ('Другое');
```

`GENERATED ALWAYS AS IDENTITY` означает, что PostgreSQL выдаёт идентификаторы автоматически при вставке новой записи. `varchar(40)` ограничивает количество символов строки. `PRIMARY KEY` одновременно требует уникальность и не допускает `NULL`.

В схеме занятия должны быть две таблицы и дополнительные ограничения длины. В `tasks` используйте `category_id integer NOT NULL REFERENCES categories(id)` и поле `completed boolean NOT NULL DEFAULT false`. При вставке задачи ID категории указывается уже существующий:

```sql
INSERT INTO tasks (title, category_id, completed)
VALUES ('Подготовить доклад', 1, false)
RETURNING id, title, category_id, completed;
```

`RETURNING` возвращает вставленную запись; его удобно использовать для ответа API после POST.

### 4. Чтение, фильтрация, сортировка и объединение таблиц

Команды `SELECT`, `WHERE`, `ORDER BY`, `JOIN` отвечают за выборку и отображение связанных данных.

```sql
-- Все невыполненные задачи, сначала новые:
SELECT id, title, category_id, completed
FROM tasks
WHERE completed = false
ORDER BY id DESC;

-- Задачи вместе с названиями категорий:
SELECT t.id, t.title, t.completed,
       c.id AS "categoryId", c.name AS "categoryName"
FROM tasks AS t
JOIN categories AS c ON c.id = t.category_id
ORDER BY t.id;
```

`AS t` и `AS c` создают короткие псевдонимы таблиц; `t.title` означает поле `title` из `tasks`. Псевдонимы `"categoryId"` и `"categoryName"` заключаются в двойные кавычки, чтобы PostgreSQL вернул нужный регистр букв в именах полей для JSON.

Поиск подстроки с игнорированием регистра выполняют через `ILIKE`:

```sql
SELECT id, title FROM tasks
WHERE title ILIKE '%отчёт%'
ORDER BY id;
```

Знак `%` — шаблон нуля или более символов. При передаче поиска из браузера шаблон формируют как **значение параметра**, а не склеивают SQL-команду из пользовательского текста.

### 5. Изменение и удаление записей

```sql
UPDATE tasks
SET completed = true
WHERE id = 5
RETURNING id, completed;

DELETE FROM tasks
WHERE id = 6
RETURNING id;
```

`WHERE` особенно важен: если забыть его, `UPDATE` или `DELETE` могут затронуть все строки таблицы. `RETURNING` помогает определить, существовала ли изменяемая запись. Если ни одна строка не вернулась, API может ответить `404`.

### 6. Как Express обращается к PostgreSQL

Пакет `pg` предоставляет объекты `Pool` и `Client`. **Пул** переиспользует ограниченное число соединений с базой, вместо того чтобы открывать новое соединение на каждый HTTP-запрос.

В файле `.env` располагается строка подключения:

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@127.0.0.1:5432/tip_tasks
PORT=3000
```

Подставьте реальные значения только в локальный `.env`. Не размещайте файл с паролем в Git и не показывайте его в отчёте. Запуск `node --env-file=.env server.js` загружает переменные окружения перед стартом программы. В `db.js`:

```javascript
import pg from 'pg';

export const pool = new pg.Pool({
  connectionString: process.env.DATABASE_URL,
  max: 5,
  connectionTimeoutMillis: 3000
});
```

`pool.query(text, values)` отправляет SQL-запрос; `result.rows` — массив возвращённых записей. Например:

```javascript
const result = await pool.query(
  'SELECT id, name FROM categories ORDER BY id'
);
console.log(result.rows);
```

Если в результате есть `category_id`, а клиент ожидает `categoryId`, используйте SQL-псевдоним `AS "categoryId"` либо преобразование объекта в JavaScript. Названия полей API должны оставаться согласованными между занятиями.

### 7. Параметризованные запросы и SQL-инъекции

Никогда не вставляйте пользовательский текст непосредственно в SQL-команду. Такая запись небезопасна:

```javascript
// НЕ ИСПОЛЬЗОВАТЬ:
const sql = `SELECT * FROM tasks WHERE title = '${req.query.q}'`;
```

Вместо склеивания строки передайте данные вторым параметром `pool.query`:

```javascript
const query = req.query.q ?? '';
const result = await pool.query(
  `SELECT id, title FROM tasks
   WHERE title ILIKE $1
   ORDER BY id`,
  [`%${query}%`]
);
```

`$1` — место для первого параметра, `$2` — для второго. Специальные символы SQL внутри строкового значения будут обработаны драйвером как данные, а не как SQL-код. Если пользователь ввёл `x' OR '1'='1`, это должно остаться поисковой строкой; нельзя изменять структуру запроса. При этом параметризация не отменяет проверку длины и типа строки.

### 8. Как перенести API занятия 12 на базу данных

Сохраняются маршруты и формат ответов, изменяется только способ получения данных. Примеры замен:

| Операция | Раньше | Теперь |
| --- | --- | --- |
| Список | `tasks.filter(...)` | `SELECT ... WHERE ...` |
| Создание | `[...tasks, newTask]` | `INSERT ... RETURNING ...` |
| Изменение | `tasks.map(...)` | `UPDATE ... RETURNING ...` |
| Удаление | `tasks.filter(...)` | `DELETE ... RETURNING ...` |
| Категории | Массив в `server.js` | Таблица `categories` |

Маршрут чтения категорий:

```javascript
app.get('/api/categories', async (req, res) => {
  try {
    const result = await pool.query(
      'SELECT id, name FROM categories ORDER BY id'
    );
    res.json(result.rows);
  } catch (error) {
    console.error('Database error:', error.code);
    res.status(503).json({ error: 'database_unavailable' });
  }
});
```

Это упрощённый вариант для учебной работы: в полноценных приложениях ошибки базы разделяются на недоступность, нарушение ограничений и прочие внутренние сбои. Нарушение внешнего ключа в PostgreSQL обозначается кодом `23503`, проверку `categoryId` дополнительно выполняют до SQL.

### 9. Транзакции: несколько действий как единое целое

Транзакция необходима, когда несколько операций должны пройти целиком или не пройти вовсе. Например, если создание задачи сопровождалось бы отдельной записью в историю изменений, эти два запроса нужно объединить.

```javascript
const client = await pool.connect();
try {
  await client.query('BEGIN');
  await client.query(
    'INSERT INTO tasks (title, category_id) VALUES ($1, $2)',
    ['Подготовить доклад', 1]
  );
  await client.query(
    'INSERT INTO tasks (title, category_id) VALUES ($1, $2)',
    ['Сделать презентацию', 1]
  );
  await client.query('COMMIT');
} catch (error) {
  await client.query('ROLLBACK');
  throw error;
} finally {
  client.release();
}
```

Пример добавляет две задачи в одной транзакции. Если вторая вставка завершается ошибкой, первая также отменяется. Важно: `BEGIN`, последующие запросы, `COMMIT` и `ROLLBACK` выполняются на **одном и том же клиенте**, поэтому внутри транзакции нельзя подменять `client.query` на `pool.query`.

### 10. Основы автоматизированного тестирования

Тест запускает функцию с определёнными входными данными и сравнивает результат с ожидаемым. Это помогает проверить исправления без многократного ручного ввода. В Node.js доступен встроенный `node:test`, а для сравнения — `node:assert/strict`:

```javascript
import test from 'node:test';
import assert from 'node:assert/strict';

function normalizeTitle(value) {
  if (typeof value !== 'string') return null;
  const title = value.trim();
  return title.length >= 1 && title.length <= 80 ? title : null;
}

test('обычная строка допустима', () => {
  assert.equal(normalizeTitle('  Доклад  '), 'Доклад');
});

test('пустая строка недопустима', () => {
  assert.equal(normalizeTitle('  '), null);
});
```

Команда `node --test` запускает тесты. **Положительный сценарий** показывает правильную работу на корректных данных; **отрицательный** — корректное отклонение ошибки. Примеры для проверки API: отсутствие задачи по ID, неизвестная категория, неверный тип `completed`, недоступная база. Тестирование HTTP удобно проводить отдельно от модульных проверок через REST-клиент.

### 11. Подготовка к эксплуатации и типовые проблемы

Для воспроизводимого запуска другому студенту нужны исходники, `package.json`, `package-lock.json`, SQL-файл, `.env.example` без секретов и README. Файл `.env`, `node_modules` и собранный `dist` обычно не сохраняют в Git. Команды из README должны выполняться по порядку на чистом учебном окружении.

| Симптом | Возможная причина | Действие |
| --- | --- | --- |
| `password authentication failed` | Неверная учётная запись БД | Проверить пользователя и пароль локально |
| `database ... does not exist` | База не создана или неверное имя | Создать базу либо исправить `DATABASE_URL` |
| `relation "tasks" does not exist` | SQL-схема не применена | Применить `001_schema.sql` в нужной базе |
| Код PostgreSQL `23503` | Категория с таким ID отсутствует | Проверить `categoryId`, вернуть `400` |
| `ECONNREFUSED` при запросе к базе | PostgreSQL остановлен или неверный порт | Проверить службу и адрес |
| Тесты не запускаются | Неверный путь импорта | Проверить файловую структуру и `.js` в ES-импорте |

Git фиксирует историю исходного кода. CI — автоматический запуск проверок после изменений в репозитории; контейнеризация — упаковка приложения и окружения. Их назначение надо понимать, но для этой шестизанятийной программы обязательны воспроизводимый локальный запуск, тесты и корректная конфигурация без опубликованных секретов.

### Дополнительные примеры и пояснения


Реляционная база данных хранит связанные записи в таблицах. Первичный ключ (`PRIMARY KEY`) идентифицирует запись, внешний ключ (`REFERENCES`) устанавливает связь, `NOT NULL`, `UNIQUE` и `CHECK` ограничивают допустимые данные. SQL-команды `SELECT`, `INSERT`, `UPDATE`, `DELETE` выполняют чтение и изменение записей. `JOIN` объединяет связанные таблицы, а сортировка и фильтрация задаются через `ORDER BY` и `WHERE`.

**Пример 1. Схема для задач и категорий.** Создать `sql/001_schema.sql`:

```sql
CREATE TABLE IF NOT EXISTS categories (
    id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name varchar(40) NOT NULL UNIQUE,
    CONSTRAINT category_name_length CHECK (length(btrim(name)) BETWEEN 1 AND 40)
);

CREATE TABLE IF NOT EXISTS tasks (
    id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    title varchar(80) NOT NULL,
    category_id integer NOT NULL REFERENCES categories(id),
    completed boolean NOT NULL DEFAULT false,
    CONSTRAINT task_title_length CHECK (length(btrim(title)) BETWEEN 1 AND 80)
);

INSERT INTO categories (name)
VALUES ('Учёба'), ('Проект'), ('Другое')
ON CONFLICT (name) DO NOTHING;
```

После создания схемы получить список с названиями категорий:

```sql
SELECT t.id, t.title, t.completed,
       c.id AS category_id, c.name AS category_name
FROM tasks AS t
JOIN categories AS c ON c.id = t.category_id
ORDER BY t.id;
```

Модуль `pg` предоставляет пул соединений `Pool`. Значения пользователя передаются отдельными параметрами `$1`, `$2`, а не вставляются в SQL-строку. Это необходимо для правильной обработки данных и защиты от SQL-инъекций.

**Пример 2. Параметризованный запрос.** Создать `db.js`:

```javascript
import pg from 'pg';

export const pool = new pg.Pool({
  connectionString: process.env.DATABASE_URL,
  max: 5,
  connectionTimeoutMillis: 3000
});

export async function createTask(title, categoryId) {
  const result = await pool.query(
    `INSERT INTO tasks (title, category_id)
     VALUES ($1, $2)
     RETURNING id, title, category_id AS "categoryId", completed`,
    [title, categoryId]
  );
  return result.rows[0];
}
```

Запрос выполняется после проверки входных данных на уровне API. Если база недоступна, сервер должен вернуть контролируемый ответ `503`, а не бесконечно ожидать соединения. Оператор `RETURNING` позволяет получить созданную запись. Связанные изменения нескольких таблиц выполняют в транзакции `BEGIN` → команды → `COMMIT`; при ошибке выполняют `ROLLBACK` через одно и то же соединение из пула.

Миграция — сохранённое изменение схемы, применяемое в определённом порядке. Для учебного приложения достаточно фиксированного SQL-файла с воспроизводимым созданием таблиц. Не удалять существующие данные при каждом запуске сервера. Учётные данные хранятся в переменных окружения, не в исходном коде и не в Git.

Проверка программ включает модульные тесты функций, интеграционные тесты HTTP API и отрицательные сценарии. В Node.js есть встроенный модуль `node:test`. Тест следует делать независимым от порядка выполнения других проверок.

**Пример 3. Модульный тест в `test/validation.test.js`.** Предполагается, что функция `normalizeTitle` из `validation.js` возвращает нормализованную строку или `null`:

```javascript
import test from 'node:test';
import assert from 'node:assert/strict';
import { normalizeTitle } from '../validation.js';

test('обрезка пробелов в названии', () => {
  assert.equal(normalizeTitle('  Задача  '), 'Задача');
});

test('пустое название недопустимо', () => {
  assert.equal(normalizeTitle('   '), null);
});

test('длина названия ограничена', () => {
  assert.equal(normalizeTitle('А'.repeat(81)), null);
});
```

В процессе подготовки приложения к запуску проверяют зависимости, отсутствие секретов в репозитории, доступность сервера, корректность сборки интерфейса и README. CI автоматически выполняет тесты при изменениях; контейнеризация описывает окружение приложения как воспроизводимую конфигурацию. В рамках занятия достаточно понимать назначение этих средств, а не создавать промышленную инфраструктуру.

## Подготовка

Потребуются Node.js, npm, локальный PostgreSQL или выданная преподавателем учебная база. Создать отдельную пустую базу `tip_tasks` и пользователя с правами на неё. В каталоге сервера занятия 12 установить `pg`:

```bash
npm install pg
```

Создать `sql/001_schema.sql`, `db.js`, `validation.js`, `test/validation.test.js`, `.env.example`, `.gitignore`. В `.env.example` указать строку-заготовку без настоящего пароля:

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@127.0.0.1:5432/tip_tasks
PORT=3000
```

Создать собственный `.env` и исключить его из Git. Для запуска с загрузкой файла окружения в поддерживаемой версии Node.js использовать `node --env-file=.env server.js`. Проверить доступность `psql`, применить схему командой `psql -d tip_tasks -f sql/001_schema.sql` (при необходимости указать `-U` и `-h`) и запустить тесты командой `node --test`.

### Порядок выполнения

**Этап 1. Создание базы.** Подключитесь через `psql` к PostgreSQL, создайте учебную базу и примените `sql/001_schema.sql`. Введите три категории и несколько задач. Проверьте `SELECT ... JOIN ...`.

**Этап 2. Подключение из Node.js.** Установите `pg`, создайте `.env.example`, реальный локальный `.env` и `db.js`. Сначала проверьте отдельным запросом чтение списка категорий, затем подключайте остальные маршруты.

**Этап 3. Перевод маршрутов на SQL.** Заменяйте маршруты по одному: чтение категорий, список задач, одна задача, создание, изменение, удаление. После каждого изменения проверяйте запрос REST-клиентом. Не меняйте имена полей API и его адреса без необходимости.

**Этап 4. Проверка ошибок.** Разделите некорректный запрос (`400`), отсутствующую запись (`404`) и недоступную базу (`503`). Для SQL используйте параметры `$1`, `$2` и никогда не вставляйте пользовательский текст в команду конкатенацией.

**Этап 5. Тестирование.** Напишите четыре модульных проверки для `validation.js` и проведите минимум три HTTP-проверки. В таблице испытаний фиксируйте входные данные, ожидаемый код, фактический код и итог.

**Этап 6. Воспроизводимость.** Остановите и снова запустите сервер; проверьте, что данные сохранились. Создайте README: установка Node.js и PostgreSQL, создание базы, применение схемы, конфигурация и запуск, проверка API, запуск тестов.
