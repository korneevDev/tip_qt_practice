## Цель

Проверить умение самостоятельно создавать приложение на JavaScript и React, использовать компоненты и состояние, проверять ввод, выполнять асинхронную загрузку и сохранять пользовательские изменения.

## Теория

### 1. Повторение перед контрольной работой

К контрольной работе должны быть известны следующие приёмы: `const` и `let`, функции, `if`, массивы объектов, `map`, `filter`, `find`, JSON, `localStorage`, `fetch`, `async/await`, обработка ошибок, React-компоненты, `props`, `useState` и `useEffect`. Все они применяются в небольшом приложении, которое работает в браузере без отдельного сервера хранения данных.

Проверьте себя на коротком примере:

```javascript
const tasks = [
  { id: 1, title: 'Отчёт', category: 'Учёба', completed: false },
  { id: 2, title: 'Сайт', category: 'Проект', completed: true }
];

const openTasks = tasks.filter(task => !task.completed);
const renamed = tasks.map(task =>
  task.id === 1 ? { ...task, title: 'Отчёт по дисциплине' } : task
);
console.log(openTasks.length);        // 1
console.log(renamed[0].title);        // Отчёт по дисциплине
console.log(tasks[0].title);          // Отчёт (старый массив не изменён)
```

Если выражения `filter`, `map` или `{ ...task }` непонятны, повторите соответствующие примеры занятия 9. Если непонятно, почему компонент обновляется после `setTasks`, вернитесь к примеру с `useState` занятия 10.

### 2. Разделение приложения на компоненты

Для проекта удобна следующая структура:

```text
practice-11/
├── public/tasks.json
├── src/
│   ├── App.jsx           # состояние и общие обработчики
│   ├── TaskForm.jsx      # поля создания записи
│   ├── TaskList.jsx      # отображение списка
│   ├── storage.js        # чтение и запись localStorage
│   └── main.jsx
├── package.json
└── README.md
```

`App` — **владелец списка**; `TaskForm` не должен хранить собственную копию всех задач. Он хранит лишь временные значения вводимых полей и при отправке сообщает родителю введённые данные. `TaskList` получает подготовленный массив для показа и функции действий.

```jsx
import { useState } from 'react';

function TaskForm({ onAdd }) {
  const [title, setTitle] = useState('');
  function handleSubmit(event) {
    event.preventDefault();
    onAdd(title);
  }
  return (
    <form onSubmit={handleSubmit}>
      <input value={title} onChange={event => setTitle(event.target.value)} />
      <button type="submit">Создать</button>
    </form>
  );
}
```

Это учебная заготовка: в контрольной работе необходимо дополнительно обработать категорию, корректность названия, очистку полей только после успешного создания и вывод текста ошибки.

### 3. Ввод и валидация данных

Сначала следует привести пользовательскую строку к нормальной форме: `trim()` удаляет пробелы по краям. Затем сравнить длину и тип. Поле `required` в HTML полезно, но оно не заменяет проверку в JavaScript.

```javascript
function normalizeTitle(input) {
  if (typeof input !== 'string') return null;
  const title = input.trim();
  if (title.length < 1 || title.length > 80) return null;
  return title;
}

console.log(normalizeTitle('  Подготовка  ')); // Подготовка
console.log(normalizeTitle('   '));           // null
```

Категорию также следует проверять по заранее определённым значениям, а не принимать любую строку. Статус `completed` должен быть логическим; строки `'false'` и `'true'` не являются логическими значениями.

### 4. Источники начальных данных: файл или localStorage

В работе есть два разных способа получения списка:

- Веб-сервер Vite отдаёт исходный файл `public/tasks.json` через `GET /tasks.json`.
- `localStorage` хранит локальные изменения пользователя между открытиями страницы.

**Правило приоритета:** если сохранение отсутствует, загрузить исходный файл. Если сохранение корректно, использовать его без дополнительного запроса. Если сохранение повреждено, показать сообщение об ошибке и не перезаписывать данные ни сетевым результатом, ни пустым массивом. Кнопка «Сброс» — отдельное явное действие пользователя.

| Ситуация | Действие программы |
| --- | --- |
| `localStorage.getItem(...) === null` | Загрузить `/tasks.json`, проверить и показать |
| Данные из `localStorage` корректны | Восстановить и показать сохранённый список |
| В хранилище повреждённый JSON | Сообщить об ошибке; сохранить исходную строку |
| Пользователь нажал «Сброс» | Получить исходный файл; заменить данные только после успешной проверки |
| Сервер недоступен при сбросе | Показать ошибку; прежнее состояние оставить |

### 5. Образец чтения локального хранения

Функция возвращает три понятных результата: отсутствие сохранения, успех или ошибку. В отличие от непосредственного `JSON.parse` в компоненте, такая функция позволяет выполнить тестирование независимо от интерфейса.

```javascript
export function readLocalTasks(key) {
  const raw = localStorage.getItem(key);
  if (raw === null) return { kind: 'missing' };

  try {
    const value = JSON.parse(raw);
    if (!Array.isArray(value)) throw new Error('Ожидался массив');
    return { kind: 'ok', value };
  } catch (error) {
    return { kind: 'invalid', message: error.message };
  }
}
```

Проверка одного лишь `Array.isArray` здесь недостаточна для выполнения контрольной: допишите полную проверку каждой записи, ID, названия, категории, статуса и числа элементов. Сохранение выполняется отдельной функцией с `try/catch`, поскольку доступ к хранилищу может оказаться запрещённым или переполненным.

### 6. Правильное обновление React-состояния

Изменения, основанные на прежнем состоянии, выполняйте через функциональную форму `setTasks(previous => ...)`. Это важно, если несколько обновлений происходят подряд. Для удаления:

```jsx
function removeTask(id) {
  setTasks(previous => previous.filter(task => task.id !== id));
}
```

Для генерации нового ID в небольшом локальном списке можно использовать `Math.max(0, ...tasks.map(t => t.id)) + 1`, но перед созданием нужно учитывать ограничение безопасного целого числа и максимальное число записей. Для производственных систем ID генерирует сервер или база данных; на этой контрольной он создаётся локально.

### 7. Поиск, фильтры и показатели

Нельзя путать **все задачи** и **показанные задачи**. `tasks` содержит исходные данные; `visibleTasks` — результат фильтрации. При поиске не нужно присваивать `setTasks(tasks.filter(...))`: так задачи из состояния исчезнут и уже не вернутся при очистке поля.

```javascript
const visibleTasks = tasks.filter(task => {
  const matchesText = task.title.toLocaleLowerCase()
    .includes(search.trim().toLocaleLowerCase());
  const matchesOpen = !onlyOpen || !task.completed;
  return matchesText && matchesOpen;
});

const completedCount = tasks.filter(task => task.completed).length;
const visibleCount = visibleTasks.length;
```

Статистику следует вычислять из состояния, а не хранить как независимые счётчики: иначе после удаления легко получить неверные значения.

### 8. Как избежать потери данных из-за асинхронности

Ошибка новичков — включить в `useEffect` загрузку исходного файла на каждом обновлении массива. После добавления задачи эффект срабатывает повторно и может заменить список исходным. Загрузку организуйте как отдельную операцию и контролируйте её завершение.

Второй риск — автоматически сохранять в `localStorage` пустой массив в момент первого рендера, **до окончания чтения сохранения или загрузки**. Для предотвращения этого можно ввести состояние начальной инициализации `ready` и разрешать запись только после восстановления корректных данных.

```jsx
const [ready, setReady] = useState(false);
// После успешного восстановления установить setReady(true).
// При ошибке чтения сохранения не разрешать автоматическую запись.
```

Конкретный способ реализации выбирается самостоятельно; важен результат: повреждённые данные не удаляются без решения пользователя, а загруженный список не теряется из-за гонки асинхронных операций.

### Дополнительные примеры и пояснения


Интерфейс React строится из небольших компонентов, а данные хранятся в состоянии. Исходный набор можно получить через `fetch`, после чего пользователь изменяет его локально. При загрузке сохранённых данных следует сначала проверить JSON и структуру записей. Асинхронный запрос не должен бесконтрольно перезаписывать уже восстановленное состояние.

При изменении записи создаётся новый массив и новый объект, в котором переопределены необходимые поля. Фильтрация строится как вычисление из основного списка: она не изменяет и не удаляет сами записи.

**Пример 1. Изменение статуса без изменения исходного массива.**

```jsx
function toggleTask(id) {
  setTasks(previous => previous.map(task =>
    task.id === id ? { ...task, completed: !task.completed } : task
  ));
}
```

**Пример 2. Применение нескольких фильтров.**

```javascript
function getVisibleTasks(tasks, query, onlyOpen) {
  const needle = query.trim().toLocaleLowerCase();
  return tasks.filter(task =>
    task.title.toLocaleLowerCase().includes(needle) &&
    (!onlyOpen || !task.completed)
  );
}
```

При работе с хранилищем различать три состояния: сохранение отсутствует, сохранение корректно, сохранение повреждено. В последнем случае необходимо сообщить об ошибке и не уничтожать исходную строку автоматически. Если запись в `localStorage` не удалась, интерфейс должен сообщить об этом, не утверждая, что результат сохранён.

