# Занятие 11. Контрольная работа №3. Планировщик учебных задач

## Цель

Проверить умение самостоятельно создавать приложение на JavaScript и React, использовать компоненты и состояние, проверять ввод, выполнять асинхронную загрузку и сохранять пользовательские изменения.

## Теория

Интерфейс React строится из небольших компонентов, а данные хранятся в состоянии. Исходный набор можно получить через `fetch`, после чего пользователь изменяет его локально. При загрузке сохранённых данных следует сначала проверить JSON и структуру записей. Асинхронный запрос не должен бесконтрольно перезаписывать уже восстановленное состояние.

При изменении записи создаётся новый массив и новый объект, в котором переопределены необходимые поля. Фильтрация строится как вычисление из основного списка: она не изменяет и не удаляет сами записи.

**Пример 1. Изменение статуса без изменения исходного массива.**

```jsx
function toggleTask(id) {
  setTasks(previous => previous.map(task =>
    task.id === id ? { ...task, completed: !task.completed } : task
  ));
}
```

**Пример 2. Применение нескольких фильтров.**

```javascript
function getVisibleTasks(tasks, query, onlyOpen) {
  const needle = query.trim().toLocaleLowerCase();
  return tasks.filter(task =>
    task.title.toLocaleLowerCase().includes(needle) &&
    (!onlyOpen || !task.completed)
  );
}
```

При работе с хранилищем различать три состояния: сохранение отсутствует, сохранение корректно, сохранение повреждено. В последнем случае необходимо сообщить об ошибке и не уничтожать исходную строку автоматически. Если запись в `localStorage` не удалась, интерфейс должен сообщить об этом, не утверждая, что результат сохранён.

## Подготовка

Создать React-проект на основе Vite; установить зависимости командой `npm install`. Подготовить компоненты `App`, `TaskForm`, `TaskList` и модуль `storage.js`. В каталоге `public` создать `tasks.json` с четырьмя корректными задачами. Начальный набор не содержит приватной информации.

Структура записи:

```json
{"id":1,"title":"Подготовить доклад","category":"Учёба","completed":false}
```

Допустимые категории: `Учёба`, `Проект`, `Другое`. Формат списка в `localStorage`: массив объектов указанной структуры; ключ `study-planner-v1`. Первоначально, если сохранение отсутствует, список загружается запросом `GET /tasks.json`. При корректном сохранении восстановление выполняется без обращения к файлу. Кнопка «Сброс» повторно запрашивает исходный файл и сохраняет его только после успешной проверки.

## Задание

Разработать приложение «Планировщик учебных задач».

| Параметр | Требование |
| --- | --- |
| ID | Уникальное положительное безопасное целое число |
| Название | 1–80 символов после `trim()` |
| Категория | Одно из значений `Учёба`, `Проект`, `Другое` |
| Статус | Логическое поле `completed` |
| Число записей | 0–100 |
| Поиск | 0–80 символов, без учёта регистра |
| Хранилище | `study-planner-v1`, JSON-массив |

1. Реализовать загрузку массива через `fetch('/tasks.json')`. Проверять HTTP-статус, структуру записей, типы, диапазоны и повтор ID; показывать загрузку и ошибку, предусмотреть повтор запроса.
2. Разделить интерфейс минимум на три компонента: основное окно приложения, форму добавления и список. Список выводить из состояния с устойчивыми ключами.
3. Добавлять задачи через управляемую форму с полями названия и категории. При неверном вводе показывать понятное сообщение и не изменять данные.
4. Реализовать смену статуса и удаление выбранной записи. Предусмотреть поиск по названию и флажок «Только невыполненные»; фильтры должны применяться совместно.
5. Вывести показатели: общее количество, количество выполненных и количество показанных задач. Для пустого результата вывести отдельное сообщение.
6. Сохранять изменения в `localStorage`, восстанавливать их после перезапуска. Некорректный сохранённый JSON не удалять автоматически; показать ошибку и предложить сброс к исходным данным.
7. Реализовать сброс через повторную загрузку `/tasks.json`. При ошибке запроса сохранить текущий список и показать диагностику.
8. Выполнить одно индивидуальное дополнение: вариант 1 — фильтр по категории; вариант 2 — сортировка по названию; вариант 3 — счётчик невыполненных по категориям; вариант 4 — кнопка «Отметить все показанные выполненными»; вариант 5 — фильтр по началу названия. Дополнение должно работать с существующим поиском.

**Проверка:** исходный набор; создание корректной и некорректной записи; выполнение и удаление; поиск без совпадений; одновременное действие фильтров; сохранение и перезапуск; пустой список; испорченный JSON в `localStorage`; HTTP 404 при сбросе и последующее восстановление. Для ошибок не допускать потери последнего корректного состояния.

**Представить:** проект на Vite/React без `node_modules`, файл исходных данных, инструкцию запуска и результаты испытаний, включая индивидуальное дополнение.
