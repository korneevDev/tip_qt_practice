# Занятие 10. Асинхронные запросы и компонентный интерфейс React

## Цель

Освоить Promise, `async`/`await`, HTTP-запросы и компонентную модель React. Создать интерфейс задач с загрузкой исходных данных и обработкой ошибок.

## Теория

### 1. От обычного JavaScript к асинхронным действиям

После занятия 9 известны переменные, функции, массивы и события. Теперь программа должна получать данные **не только из своей памяти**, но и по сети. Сетевой запрос выполняется некоторое время; ожидание нельзя организовывать длительным циклом, иначе интерфейс перестанет реагировать на пользователя.

JavaScript выполняет код последовательно, но может поручать среде выполнения асинхронные операции. Когда результат станет доступен, продолжение программы будет запланировано без блокировки интерфейса. Важно различать **выполнение запроса** и **получение результата**.

```javascript
console.log('1. До запроса');
setTimeout(() => console.log('3. Отложенная операция'), 0);
console.log('2. После постановки операции в очередь');
```

Порядок строк в консоли: 1, 2, 3. `setTimeout` в данном примере лишь демонстрирует отложенное выполнение; в реальном приложении данные обычно приходят через HTTP.

### 2. Promise, async/await и обработка ошибок

`Promise` представляет результат, который появится позже. У него могут быть состояния ожидания, успешного завершения и ошибки. Метод `.then()` получает успешное значение, `.catch()` — ошибку. Конструкция `async/await` позволяет написать ту же логику более последовательно.

```javascript
function getExampleTask() {
  return Promise.resolve({ id: 1, title: 'Прочитать тему', completed: false });
}

async function showExample() {
  try {
    const task = await getExampleTask();
    console.log(task.title);
  } catch (error) {
    console.error('Не удалось получить данные:', error.message);
  } finally {
    console.log('Операция завершена');
  }
}
showExample();
```

`async` ставится перед функцией. `await` допустим внутри `async`-функции (и на верхнем уровне ES-модуля). Если операция завершилась с ошибкой, управление переходит в `catch`. Секция `finally` выполняется и после успеха, и после ошибки; поэтому в ней удобно отключать индикатор загрузки.

### 3. HTTP: адрес, метод, тело и статус

При обмене через HTTP браузер отправляет запрос на адрес, а сервер возвращает ответ. Основные части запроса: метод, URL, заголовки и необязательное тело. В адресе `http://127.0.0.1:5173/tasks.json` число `5173` — порт локального сервера разработки.

| Метод | Обычное назначение | Пример |
| --- | --- | --- |
| `GET` | Чтение данных | Получить список задач |
| `POST` | Создание | Передать новую задачу |
| `PATCH` | Частичное изменение | Изменить статус |
| `DELETE` | Удаление | Удалить запись |

Статус `200` обычно указывает на успех, `404` — отсутствие ресурса, `500` — ошибку на сервере. Даже при статусе `404` браузер **может успешно получить HTTP-ответ**. Поэтому `fetch()` не всегда бросает исключение: необходимо отдельно проверить `response.ok`.

```javascript
async function readJson(url) {
  const response = await fetch(url);
  if (!response.ok) {
    throw new Error(`Сервер ответил: ${response.status}`);
  }
  return response.json();
}
```

Вызов `response.json()` также асинхронный: он читает тело и разбирает JSON. Если JSON некорректен, возникает ошибка. В приложении следует проверять и структуру полученного значения (например, действительно ли оно является массивом задач).

### 4. Первое упражнение с fetch до знакомства с React

Создайте в проекте обычный HTML-файл и `public/tasks.json` (после создания Vite-проекта). Пример содержимого:

```json
[
  {"id": 1, "title": "Повторить массивы", "completed": false},
  {"id": 2, "title": "Изучить запросы", "completed": true}
]
```

В браузере с открытым локальным сервером Vite введите в консоль:

```javascript
fetch('/tasks.json')
  .then(response => {
    if (!response.ok) throw new Error(String(response.status));
    return response.json();
  })
  .then(items => console.log(items.length))
  .catch(error => console.error(error.message));
```

Затем временно переименуйте файл, повторите запрос и посмотрите вкладку **Network**. Там находятся URL, метод, HTTP-код, время ответа и тело. После упражнения верните имя файла. Такое упражнение помогает увидеть, почему сетевые данные не равнозначны обычному массиву, который уже находится в памяти.

### 5. Что такое React и зачем он нужен

При работе с DOM в занятии 9 разработчик сам создавал `<li>`, обновлял надписи кнопок и очищал контейнер. React использует другой подход: **интерфейс описывается как функция от текущих данных**. Изменение состояния вызывает повторное построение нужной части интерфейса.

React-приложение обычно состоит из компонентов — JavaScript-функций, имена которых начинаются с прописной буквы и которые возвращают JSX. JSX выглядит как HTML, но является синтаксисом JavaScript для описания элементов интерфейса:

```jsx
function Greeting({ name }) {
  return <p>Здравствуйте, {name}!</p>;
}

export default function App() {
  return (
    <main>
      <h1>Учебное приложение</h1>
      <Greeting name="Ирина" />
    </main>
  );
}
```

`name` внутри `Greeting` — это **props**, входные данные компонента. Значение `name="Ирина"` передаётся родителем. Фигурные скобки `{name}` вставляют результат выражения. JSX требует единственного корневого элемента в возвращаемой разметке; несколько соседних элементов можно завернуть во фрагмент `<>...</>`.

### 6. useState: как компонент запоминает введённые данные

Обычная переменная внутри функции компонента не подходит для хранения состояния между обновлениями интерфейса. Хук `useState` возвращает текущее значение и функцию его изменения.

```jsx
import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Нажатий: {count}</p>
      <button type="button" onClick={() => setCount(previous => previous + 1)}>
        Увеличить
      </button>
    </div>
  );
}
```

`useState(0)` устанавливает начальное значение. `setCount` сообщает React о необходимости обновить состояние. Обработчику `onClick` передают **функцию**. Запись `onClick={setCount(1)}` неверна для этого случая: она вызывает обновление сразу во время рендеринга, а не после нажатия.

Для полей ввода используют **управляемые компоненты**: React хранит значение и изменяет его в ответ на событие.

```jsx
const [query, setQuery] = useState('');
<input value={query} onChange={event => setQuery(event.target.value)} />
```

Чтобы изменить массив задач, не применяйте `tasks.push(...)` и `task.completed = true` к состоянию. Вместо этого создавайте новые значения через `map`, `filter` и spread-оператор, как в занятии 9.

### 7. Компоненты, props и вывод списков

Состояние списка обычно хранится в `App`, который передаёт дочерним компонентам данные и обработчики. Такой подход называют подъёмом состояния: несколько компонентов получают согласованные значения из одного источника.

```jsx
function TaskRow({ task, onToggle }) {
  return (
    <li>
      <span>{task.title}</span>
      <button type="button" onClick={() => onToggle(task.id)}>
        {task.completed ? 'Вернуть' : 'Выполнить'}
      </button>
    </li>
  );
}

function TaskList({ tasks, onToggle }) {
  return (
    <ul>
      {tasks.map(task => (
        <TaskRow key={task.id} task={task} onToggle={onToggle} />
      ))}
    </ul>
  );
}
```

`key` нужен React для различения элементов при обновлении списка. Его следует задавать по стабильному уникальному ID записи, а не по позиции в массиве, которая меняется после удаления и фильтрации.

### 8. useEffect: связь с внешними системами

Загрузка списка по HTTP — побочный эффект: она взаимодействует с внешним источником данных. Хук `useEffect` позволяет запустить такую операцию после появления компонента. Пустой массив зависимостей `[]` означает отсутствие зависимостей от props или состояния. В режиме разработки React Strict Mode эффект может запускаться дополнительный раз для проверки корректности очистки: к этому необходимо быть готовым.

```jsx
import { useEffect, useState } from 'react';

function RemoteCounter() {
  const [count, setCount] = useState(null);
  const [error, setError] = useState('');

  useEffect(() => {
    const controller = new AbortController();
    async function load() {
      try {
        const response = await fetch('/tasks.json', { signal: controller.signal });
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const data = await response.json();
        if (!Array.isArray(data)) throw new Error('Ожидался массив');
        if (!controller.signal.aborted) setCount(data.length);
      } catch (err) {
        if (!controller.signal.aborted) setError(err.message);
      }
    }
    load();
    return () => controller.abort();
  }, []);

  if (error) return <p role="alert">{error}</p>;
  return <p>Количество: {count ?? 'загрузка...'}</p>;
}
```

В большом проекте следует дополнительно учитывать гонки запросов. В данной работе достаточно отмены старого запроса при уходе со страницы и отдельной кнопки повторной загрузки.

### 9. Организация React-проекта с Vite

Команда `npm create vite@latest ...` создаёт шаблон. `npm` — менеджер пакетов; `package.json` содержит сведения о проекте, зависимости и команды запуска; `node_modules` — установленные библиотеки. `npm install` восстанавливает зависимости по файлам проекта. `npm run dev` запускает сервер разработки, а `npm run build` создаёт сборку.

Базовая структура:

```text
practice-10/

│   └── tasks.json
└── src/
    ├── main.jsx
```

Файл `src/main.jsx` обычно содержит `createRoot(document.getElementById('root')).render(<App />)`. В шаблоне Vite он уже создан. Папка `public` публикуется по корневым URL: `public/tasks.json` доступен через `/tasks.json`, а **не** `/public/tasks.json`.

### 10. Проверка полученных данных и повторная загрузка

Полученные с сервера данные нельзя считать корректными только потому, что `response.json()` выполнился успешно. Например, текст `{"id": 1}` является правильным JSON, но не массивом задач. Создайте функцию `validateTasks(data)`, которая проверяет:

1. `Array.isArray(data)` и длину до 100.
2. Каждую запись: объект, целочисленный уникальный `id > 0`, `title` длиной 1–80 после обрезки пробелов, логическое `completed`.
3. Отсутствие повторяющихся ID с помощью `Set`.
4. Только после полной проверки — передачу массива в состояние.

Состояния **загрузка**, **ошибка**, **успех** должны быть явными. При ошибке повторной загрузки не заменяйте уже показанные правильные данные на пустой массив.

### 11. Частые проблемы при изучении React

| Симптом | Причина | Решение |
| --- | --- | --- |
| `npm` не найден | Node.js не установлен или терминал не перезапущен | Установить Node.js LTS и снова открыть терминал |
| На странице видно `public/tasks.json` как 404 | Неверный URL | Использовать `/tasks.json` |
| Компонент не отображается | Имя начинается с маленькой буквы, отсутствует экспорт или ошибка JSX | Проверить `export`, `import` и синтаксис |
| Кнопка вызывает действие при открытии страницы | В `onClick` передан результат вызова | Использовать стрелочную функцию |
| Список не обновляется после `push` | Массив состояния изменён на месте | Вернуть новый массив через `setTasks` |
| React предупреждает об отсутствии `key` | Элементы списка без стабильных ключей | Добавить `key={task.id}` |
| Запрос 404, а ошибка не отображается | Не проверяется `response.ok` | Добавить проверку статуса и `catch` |

Перед выполнением задания сделайте три коротких упражнения: создайте компонент `Greeting`, затем счётчик на `useState`, затем загрузите и выведите количество записей из `/tasks.json`. После этого переходите к полноценному приложению с фильтрами и списком.

### Дополнительные примеры и пояснения


HTTP связывает клиент и сервер запросами и ответами. Метод `GET` получает данные, `POST` создаёт ресурс, `PATCH` частично изменяет его, `DELETE` удаляет. Код состояния `200` означает успешный ответ, `201` — создание ресурса, `400` — ошибку запроса, `404` — отсутствие ресурса, `500` — ошибку сервера. Тело ответа часто передаётся в формате JSON. CORS ограничивает чтение ответов между разными источниками в браузере; его разрешение настраивается сервером, а не отключается клиентским кодом.

Асинхронные операции не останавливают интерфейс на время ожидания. `fetch()` возвращает Promise; выражение `await` ожидает результат внутри асинхронной функции. После завершения операции продолжение выполняется через очередь задач JavaScript. `fetch` не отклоняет Promise автоматически для HTTP 404 и 500: статус необходимо проверять самостоятельно.

**Пример 1. Загрузка JSON с проверкой ответа.** Создать файл `src/api.js`:

```javascript
export async function loadTasks(signal) {
  const response = await fetch('/tasks.json', {
    method: 'GET',
    headers: { Accept: 'application/json' },
    signal
  });
  if (!response.ok) {
    throw new Error(`Ошибка HTTP: ${response.status}`);
  }
  const data = await response.json();
  if (!Array.isArray(data) || data.length > 100) {
    throw new Error('Неверный формат ответа');
  }
  return data;
}
```

Обработка ошибки обычно выполняется через `try`/`catch`/`finally`. Для временной локальной ошибки сети не следует заменять успешно загруженные данные пустым списком. `AbortController` позволяет отменить запрос, если компонент больше не использует его результат.

React строит интерфейс из компонентов. `props` передают данные от родительского компонента, `useState` хранит изменяемое состояние, `useEffect` запускает побочный эффект, например загрузку данных. В JSX выражения заключаются в фигурные скобки; для списка нужны устойчивые ключи (`key`). Обработчики React получают функции, а не строки кода.

**Пример 2. Компонент списка.**

```jsx
export function TaskList({ tasks, onToggle }) {
  if (tasks.length === 0) return <p>Записей нет</p>;
  return (
    <ul>
      {tasks.map(task => (
        <li key={task.id}>
          <span>{task.title}</span>
          <button type="button" onClick={() => onToggle(task.id)}>
            {task.completed ? 'Отменить выполнение' : 'Выполнить'}
          </button>
        </li>
      ))}
    </ul>
  );
}
```

React экранирует текстовое содержимое JSX. Ввод строки пользователя не должен приводить к выполнению HTML-кода. Не изменять массив состояния непосредственно через `push()` и изменение свойств объектов: для корректного обновления создавать новую коллекцию.

**Пример 3. Асинхронная загрузка в компоненте.**

```jsx
import { useEffect, useState } from 'react';
import { loadTasks } from './api.js';

export function App() {
  const [tasks, setTasks] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState('');

  useEffect(() => {
    const controller = new AbortController();
    (async () => {
      try {
        const incoming = await loadTasks(controller.signal);
        if (!controller.signal.aborted) setTasks(incoming);
      } catch (err) {
        if (!controller.signal.aborted) setError(err.message);
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    })();
    return () => controller.abort();
  }, []);

  if (loading) return <p>Загрузка…</p>;
  if (error) return <p role="alert">{error}</p>;
  return <p>Загружено: {tasks.length}</p>;
}
```

Компонент выше демонстрирует только загрузку; отображение, поиск и изменение задач реализуются в задании. Разные компоненты могут владеть состоянием, однако общий список удобно хранить у ближайшего общего родителя и передавать обработчики вниз.

### Порядок выполнения

**Этап 1. Знакомство с инструментами.** Запустите шаблон Vite, откройте страницу и измените заголовок в `App.jsx`. Убедитесь, что браузер автоматически обновляет страницу при сохранении файла.

**Этап 2. Подготовка данных.** Создайте `public/tasks.json` и проверьте его открытие в браузере по адресу `/tasks.json`. На время отладки можно использовать две записи; к сдаче подготовьте не менее трёх.

**Этап 3. Загрузка.** Создайте модуль `src/api.js`; его функция должна проверять HTTP-код, JSON и поля записей. В `App` сделайте состояния `tasks`, `loading`, `error` и вызов загрузки через `useEffect`.

**Этап 4. Компоненты.** В `TaskList` передайте `tasks` и `onToggle` через props. Состояние изменяйте только через `setTasks`, не присваивайте значения полям исходного массива.

**Этап 5. Поиск и фильтр.** Добавьте управляемые элементы `input` и `select`; вычисляйте `visibleTasks` из `tasks`, строки поиска и выбранного статуса. Для пустого результата показывайте сообщение вместо пустого списка.

**Этап 6. Ошибки и повтор запроса.** Реализуйте кнопку повторной загрузки. Проверьте, что 404, повреждённый JSON и неверная структура показывают предупреждение и не стирают ранее загруженное содержимое.

**Минимальный результат на занятии:** React-проект запускается, загружает файл по HTTP и выводит данные в отдельном компоненте. **Полный результат:** реализованы все фильтры, изменение статуса, сообщения о загрузке и об ошибке.
