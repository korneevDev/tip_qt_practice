# Занятие 8. Контрольная работа №2. Анализатор обращений

## Цель

Проверить умение применять обработку строк, регулярные выражения и файловые операции в прикладной программе.

## Теория

Запись проверяется последовательно: количество полей, формат номера, адрес электронной почты, описание. Обращение к элементу списка допускается после проверки его наличия. `split(';', Qt::KeepEmptyParts)` сохраняет позиции пустых полей.

Для проверки поля целиком используются границы `\A` и `\z`. Поиск подстроки выполняется через `contains(query, Qt::CaseInsensitive)`. Ошибочная запись участвует в диагностике, но не включается в результаты поиска. Номера строк соответствуют исходному файлу, включая пустые строки.

**Пример 1. Проверка записи.** Функция размещается вне класса в `.cpp`. Подключить `<QStringList>` и `<QRegularExpression>`. Порядок проверок определяет первую выводимую ошибку.

```cpp
static bool parseTicket(const QString &line,
                        QStringList &result, QString &error)
{
    error.clear();
    QStringList fields = line.split(';', Qt::KeepEmptyParts);
    if (fields.size() != 3) {
        error = "Ожидалось три поля";
        return false;
    }
    for (QString &field : fields) field = field.trimmed();
    const QRegularExpression numberRe(R"(\A[1-9][0-9]{2}\z)");
    const QRegularExpression emailRe(
        R"(\A[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\z)");
    if (!numberRe.match(fields[0]).hasMatch())
        error = "Номер должен быть от 100 до 999";
    else if (fields[1].size() < 6 || fields[1].size() > 254
             || !emailRe.match(fields[1]).hasMatch())
        error = "Неверный email";
    else if (fields[2].isEmpty() || fields[2].size() > 500)
        error = "Описание должно содержать 1–500 единиц UTF-16";
    if (!error.isEmpty()) return false;
    result = fields;
    return true;
}
```

**Пример 2. Обход исходных строк.** Фрагмент выполняется в обработчике анализа после проверки общих ограничений. Списки ошибок и результатов создаются заново при каждом вызове.

```cpp
const QStringList lines = ui->sourceEdit->toPlainText().split('\n');
const QString query = ui->queryEdit->text().trimmed();
QStringList errors, matches;
for (qsizetype i = 0; i < lines.size(); ++i) {
    if (lines[i].trimmed().isEmpty()) continue;
    QStringList fields;
    QString error;
    if (!parseTicket(lines[i], fields, error)) {
        errors.append(QString("Строка %1: %2").arg(i + 1).arg(error));
        continue;
    }
    if (!query.isEmpty() && fields[2].contains(query, Qt::CaseInsensitive))
        matches.append(fields.join(';'));
}
```

`continue` исключает неверную запись из поиска. Для включения результатов в отчёт применяется `matches.join('\n')`. Счётчики, список email и экспорт необходимо реализовать согласно заданию.

Средства разработки: C++17, Qt 6.2 или новее, Qt Creator, CMake; тип проекта — Qt Widgets Application, класс главного окна — `MainWindow`. Исходные файлы сохранять в UTF-8. Интерфейс размещать в компоновках. Имена объектов задавать через свойство `objectName`.

Подготовить поля `sourceEdit`, `queryEdit`, `resultEdit` и кнопки открытия, сохранения исходного текста, анализа и экспорта. Обязательные средства: `QString`, `QStringList`, `QRegularExpression`, `QFile`, `QTextStream`, `QFileDialog`, `QSaveFile`, отдельная функция проверки записи.

## Задание

Разработать приложение «Анализатор обращений», обеспечивающее загрузку, проверку, поиск и экспорт отчёта.

| Параметр | Требование |
|---|---|
| Файл | UTF-8, 0–2097152 байт |
| Непустые строки | 0–10000 |
| Запись | Ровно три поля: `номер;email;описание` |
| Номер | Три цифры, значение 100–999 |
| Email | 6–254 единицы UTF-16; шаблон `\A[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\z` |
| Описание | 1–500 единиц UTF-16 после `trimmed()`, без `;` |
| Запрос | 0–100 единиц UTF-16 после `trimmed()` |

1. Пропускать пустые строки, удалять внешние пробелы каждого поля. Повторяющиеся номера и email разрешены.
2. Вывести число непустых строк, корректных и ошибочных записей. Для каждой ошибки указать физический номер строки и первую причину в порядке проверки полей.
3. Найти корректные записи, описание которых содержит запрос без учёта регистра. Вывести их в исходном порядке. При пустом запросе вывести «Поиск не задан» и ноль совпадений.
4. Включить в отчёт найденные обращения, email всех корректных записей с повторениями и список ошибок. Для пустых списков вывести «Нет».
5. Сохранять отчёт в UTF-8. При превышении общих ограничений не формировать частичный отчёт. Ошибка отдельной записи не прерывает проверку остальных.
6. Обеспечить обработку отмены файловых диалогов, ошибок чтения и записи, а также защиту несохранённых изменений. Повторный анализ не должен увеличивать счётчики.

**Контрольный файл:**

```text
101;anna@example.com;Не запускается игра

102;boris@example.com;Нет звука
103;invalid;Ошибка игры
104;anna@example.com;Игра закрывается
105;olga@example.com;Вопрос
ошибочная строка
```

Ожидаемый результат: 6 непустых строк, 4 корректные записи, 2 ошибки — строки 4 и 7. Запрос `игра` даёт обращения 101 и 104; `ЗВУК` — 102. Список email содержит 4 адреса, включая повтор. Дополнительно подготовить три собственные корректные записи и по одной записи с неверным номером, пустым описанием и лишним разделителем. Представить входной файл и отчёт.
